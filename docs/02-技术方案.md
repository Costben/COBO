# 技术方案

> 目标：做一个功能完整、可长期维护的第三方微博客户端。
> 网络层采用双通道路由：客户端登录账号走 `api.weibo.cn/2/` 容器协议（`gsid` 长期会话），网页登录与纯本地访客模式保留 `m.weibo.cn` / `weibo.com` Web API。

## 1. 总体路线

| 层 | 选择 | 说明 |
| :--- | :--- | :--- |
| 客户端通道 | `api.weibo.cn/2/` 容器协议 | 客户端登录（`LOGIN_TYPE_CLIENT`）主通道，凭 `gsid` + `s`/`i`/`cum` 认证，不依赖网页 `SUB` |
| 网页/游客通道 | `m.weibo.cn` + `weibo.com` Web API | 网页登录（`LOGIN_TYPE_WEB`）与纯本地模式完整保留该通道，Cookie 滚动续命 |
| 协议层 | `Repo` 统一调度 | 对上层页面暴露同一套模型与状态，切换登录方式不动 UI |

把协议层做成接口，未来接入任何一条通道只需换一个实现。

## 2. 技术栈

| 层 | 实际选择 | 说明 |
| :--- | :--- | :--- |
| 语言 | Kotlin | 协程写异步 |
| UI | Jetpack Compose + COUI 组件库 | 界面走 `coui-ui`（`io.github.costben.coui17`）的 ColorOS 观感，Material 3 只作底层基础 |
| 架构 | 单 Activity + Compose 导航 + 数据仓库 | `data/Repo.kt` 持有请求与页面状态，没有单独的 ViewModel 层 |
| 网络 | OkHttp 4 + `org.json` | 项目没有引入 `kotlinx.serialization`，JSON 用 Android 自带的 `org.json` |
| 图片 | Coil 3 | 原生适配 Compose |
| 视频 | Media3 (ExoPlayer) | |
| 本地存储 | JSON 文件 + SharedPreferences | 没有 Room / SQLite / DataStore，详见第 4 节 |
| 登录凭据 | Android Keystore AES-256-GCM | 见 4.2 |
| DI | 无 | `App` 单例对象在 `Application.onCreate` 里手动装配 |
| 分页 | 手写 | 列表状态在内存里，首页另有续看快照 |
| 后台任务 | 无 WorkManager | 更新检查在应用内完成 |

最低 SDK 26（Android 8.0），当前 `compileSdk` / `targetSdk` 37。

## 4. 数据模型（最小集）

```kotlin
data class Account(
    val uid: String,
    val screenName: String,
    val avatar: String,
    val cookie: String,
    val expiresAt: Long,
)

data class Status(
    val id: String,
    val mid: String,
    val text: String,
    val createdAt: Long,
    val user: User,
    val repostsCount: Int,
    val commentsCount: Int,
    val attitudesCount: Int,
    val pics: List<Pic>,
    val video: Video?,
    val retweeted: Status?,
    val source: String,
    val regionName: String?,
)

data class Comment(
    val id: String,
    val text: String,
    val user: User,
    val createdAt: Long,
    val likeCount: Int,
    val reply: Comment?,
)
```

上面的模型只在内存里流转，**不落数据库**：项目没有引入 Room / SQLite，持久化只有 JSON 文件和 SharedPreferences 两种。

### 4.1 文件与偏好

| 位置 | 文件 | 内容 | 加密 |
| :--- | :--- | :--- | :--- |
| `filesDir/` | `session.json` | 当前会话：cookie 表、uid、gsid、accessToken、过期时间 | 是 |
| `filesDir/` | `accounts.json` | 多账号列表，每个账号一份 cookie | 是 |
| `filesDir/` | `visitor.json` | 纯本地模式的访客 cookie | 是 |
| `filesDir/` | `device.json` | 设备号、`aid` / `did` | 否 |
| `filesDir/` | `drafts.json` | 草稿 | 否 |
| `filesDir/` | `history.json` | 浏览历史 | 否 |
| `filesDir/` | `favorites.json` | 本地收藏（上限 500 条，跨账号共享） | 否 |
| `filesDir/` | `follows.json` | 关注标记 | 否 |
| `filesDir/` | `chat-seen.json` | 私信已读进度（服务端没有已读接口） | 否 |
| `filesDir/http-cache/` | `<sha256>.json` | GET 响应缓存，16 MB 上限 | 否 |
| `filesDir/feed-snapshots/` | `<owner>/<key>.json` | 首页时间线续看快照，7 天过期 | 否 |
| `SharedPreferences("app")` | — | 主题、字号、强调色、栏位、开关、搜索历史、滚动位置 | 否 |
| `cacheDir/` | — | Coil 图片缓存、实况图、视频分片、更新包 | 否 |

写入统一走「临时文件 + rename」，进程被杀不会留下半截 JSON。

### 4.2 登录凭据加密

`session.json`、`accounts.json`、`visitor.json` 用 Android Keystore 里的 AES-256-GCM 密钥加密
（`data/SecretStore.kt`）。密钥由 Keystore 生成且不可导出，源码和 APK 开源也拿不到；能解开的只有这台设备上以本应用 UID 运行的进程。文件格式 `v1:` + base64(iv || ciphertext)。

这层防的是设备上的静态数据：root、备份导出、同 UID 的调试工具、丢失的手机。它防不住已经能在设备上以本应用身份执行代码的人——那种情况下直接读进程内存即可。加密不替代 HTTPS，也不改变 cookie 自身的有效期。

没有 `v1:` 前缀的旧文件按明文读，下次写入自动转密文；Keystore 不可用时退回明文并记日志，不阻断登录。

## 6. 关键实现细节

### 6.1 富文本

微博正文不是纯文本，包含：

- `@用户` → 可点击，跳主页
- `#话题#` → 跳话题页
- `http(s)://...` → 内置浏览器
- `[表情]` → 替换为图片 Span
- 长文 → `statuses/extend` 或 `article_show`

做一个 `WeiboTextParser`，输出 `AnnotatedString`（Compose）。

### 6.2 九宫格

- 1 张：大图，按原比例
- 2–4 张：两列
- 5–9 张：三列
- 超过 9 张：只显示前 9 张 + `+N`

图片 URL 有多档：`thumbnail` / `bmiddle` / `large` / `or480` / `wap360` / `wap720`，按场景选。

### 6.3 视频

- 列表内静音自动播放（可选）
- 详情页全屏、倍速、清晰度切换
- `media_info.stream_url` 直接播放

### 6.4 缓存

- 接口：`data/CacheStore.kt` 把 GET 响应按 `SHA-256(cookie + url)` 存成 JSON，16 MB 封顶，超出按最旧淘汰。列表允许过期，进页面先展示缓存，下拉刷新或显式重载才请求网络。
- 首页续看：`data/FeedSnapshot.kt` 按账号保存整份已拉列表和游标（最多 500 条），冷启动直接填回，超过 7 天丢弃。
- 图片：Coil 3 的内存 + 磁盘缓存。
- 离线：只覆盖已读正文与图片，不提供完整离线阅读。

### 6.5 主题

- 深色模式
- 自定义主色、字号
- Compose 下用 `ColorScheme` + `CompositionLocal` 实现

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 微博接口变更 | 页面数据缺失 | 协议层抽象；错误可降级 |
| 账号风控 | 登录态失效 | 不模拟官方 UA；控制请求频率；不做自动化刷量 |
| Cookie 过期 | 需重新登录 | 过期检测 + 一键重登，账号数据本地保留 |
| 维护成本 | 长期腐烂 | 模块化 + 端到端测试 |

## 8. 取舍说明

- 容器端（`api.weibo.cn/2`）按 Share 3.9.6 的做法复刻了客户端通道：`WeiboSpoofContext` + `libwbutil.so`（`10B6395010`）算 `s`/`i`/`cum`、`account/login` 拿 `gsid` 并自动续期，客户端登录账号的所有核心读写请求直接走 `ContainerApi`，不再受 `m.weibo.cn` 网页 `SUB` 失效影响。
- 网页端（`m.weibo.cn` / `weibo.com`）作为独立通道完整保留给网页登录账号与纯本地访客模式：响应里的 `Set-Cookie`（仅限携带登录态 `SUB` 的请求）收进域名表，冷启动时按浏览器方式做一次心跳续期；`http-cache` 仅缓存 `ok == 1` 的正常响应。
- 不复用他人图标、插画、启动图，全部自绘。
- 不在公开产品里做自动化刷量、养号等行为。
