# 技术方案

> 目标：做一个功能完整、可长期维护的第三方微博客户端。
> 网络层以 `m.weibo.cn` Web API 为主（Cookie 会话），官方开放平台作为可替换的第二条 Transport。

## 1. 总体路线

| 层 | 选择 | 说明 |
| :--- | :--- | :--- |
| 网络 | `m.weibo.cn` Web API | 网页登录一次后复用 Cookie，接口稳定、无需私有签名 |
| 备选 | 官方开放平台 `api.weibo.com/2/` | 需要 AppKey，覆盖 30–50% 功能，作为降级通道 |
| 协议层 | 接口化 `Transport` | 换实现不动 UI |

把协议层做成接口，未来接入任何一条通道只需换一个实现。

## 2. 技术栈

| 层 | 选择 | 理由 |
| :--- | :--- | :--- |
| 语言 | Kotlin | 协程替代 RxJava，代码量减半 |
| UI | Jetpack Compose + Material 3 | 声明式 UI，主题与动效成本低 |
| 架构 | MVVM + Repository | Compose 下状态驱动更顺 |
| 网络 | OkHttp 4 + kotlinx.serialization | 轻量、可控、便于抓包对照 |
| 图片 | Coil | 原生适配 Compose |
| 视频 | Media3 (ExoPlayer) | 维护活跃 |
| 数据库 | Room | 结构化缓存 |
| 键值 | DataStore / SharedPreferences | 设置项 |
| DI | Hilt | |
| 分页 | Paging 3 | 信息流天然适配 |
| 后台任务 | WorkManager | 定时刷新、上传重试 |

最低 SDK 26（Android 8.0）。

## 3. 模块拆分

```
app/
├── core/
│   ├── network/        # OkHttp、Cookie、公共参数、错误映射
│   ├── auth/           # 账号、Cookie、多账号切换
│   ├── database/       # Room
│   ├── datastore/      # 设置项
│   ├── designsystem/   # 主题、颜色、字体、图标
│   └── common/         # 时间格式化、富文本、Span
├── feature/
│   ├── timeline/       # 关注流 / 推荐流 / 好友圈
│   ├── statusdetail/   # 正文、评论、转发链
│   ├── publish/        # 发博、图片、可见性
│   ├── profile/        # 个人主页、资料、关注/粉丝
│   ├── search/         # 搜索、热搜、话题
│   ├── message/        # 私信、通知
│   ├── settings/       # 设置、主题、缓存
│   └── login/          # 网页登录、Cookie 抓取、验证
└── protocol/
    ├── web/            # m.weibo.cn 实现（默认）
    └── official/       # 开放平台实现（可选）
```

## 5. 里程碑

### M0 — 骨架（1 周）

- 建工程、Hilt、Navigation、主题
- 底部三 Tab（微博 / 消息 / 我）
- 空列表 + 下拉刷新 + 加载更多
- 验收：能跑，能切 Tab，深浅色正常

### M1 — 登录（1–2 周）

- 官方网页登录（全屏 WebView，自动抓 Cookie）
- Cookie 持久化、多账号切换
- 验收：登录后能拿到自己的昵称头像

### M2 — 信息流（2 周）

- 推荐流 `containerid=102803`、关注流 `feed/friends`、好友圈 `feed/circle`
- 微博卡片：文字、九宫格、转发、视频封面、来源、时间
- 富文本：@、话题、链接、表情
- 验收：滚动流畅，图片不闪，长文可展开

### M3 — 详情与互动（2 周）

- 正文页、评论列表（热度 / 时间双排序）
- 转发 / 评论 / 点赞
- 验收：动作成功并在列表同步

### M4 — 发布（2 周）

- 文字 + 多图 + 话题 + @
- 图片上传进度、失败重试
- 草稿
- 验收：发一条带 9 图的微博

### M5 — 个人主页与关系（1–2 周）

- 主页、关注/粉丝、关注/取关
- 我的赞、我的收藏

### M6 — 搜索与热门（1 周）

- 搜索、热搜榜、话题页

### M7 — 私信（2 周，可选）

- 会话列表、聊天、图片、未读数

### M8 — 打磨（持续）

- 主题、字号、图标切换
- 缓存策略、离线阅读
- 无障碍、深色模式、大屏适配

## 6. 关键实现细节

### 6.1 富文本

微博正文不是纯文本，包含：

- `@用户` → 可点击，跳主页
- `#话题#` → 跳话题页
- `http(s)://...` → 内置浏览器
- `[表情]` → 替换为图片 Span
- 长文 → `statuses/extend` 或 `article_show`

做一个 `WeiboTextParser`，输出 `AnnotatedString`（Compose）。

### 6.2 九宫格

- 1 张：大图，按原比例
- 2–4 张：两列
- 5–9 张：三列
- 超过 9 张：只显示前 9 张 + `+N`

图片 URL 有多档：`thumbnail` / `bmiddle` / `large` / `or480` / `wap360` / `wap720`，按场景选。

### 6.3 视频

- 列表内静音自动播放（可选）
- 详情页全屏、倍速、清晰度切换
- `media_info.stream_url` 直接播放

### 6.4 缓存

- 信息流：内存 + Room，按 `max_id` / `since_id` 分页缓存
- 图片：Coil 磁盘缓存
- 离线：只缓存已读的正文和图片

### 6.5 主题

- 深色模式
- 自定义主色、字号
- Compose 下用 `ColorScheme` + `CompositionLocal` 实现

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 微博接口变更 | 页面数据缺失 | 协议层抽象；错误可降级 |
| 账号风控 | 登录态失效 | 不模拟官方 UA；控制请求频率；不做自动化刷量 |
| Cookie 过期 | 需重新登录 | 过期检测 + 一键重登，账号数据本地保留 |
| 维护成本 | 长期腐烂 | 模块化 + 端到端测试 |

## 8. 不做的事

- 不模拟官方客户端 UA 去骗取接口能力。
- 不复用任何第三方客户端的私有签名库或激活服务。
- 不复用他人图标、插画、启动图，全部自绘。
- 不在公开产品里做自动化刷量、养号等行为。
