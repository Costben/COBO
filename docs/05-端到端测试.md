# 07 · 端到端测试

`frontend/app/src/androidTest/kotlin/com/cobo/app/e2e/` 是一套跑在真机上的端到端测试，直接使用设备上已登录的会话，覆盖 UI 导航、真实接口解析、磁盘缓存和本地草稿。默认只读：不会发微博、评论、转发，也不会退出登录。

## 运行

```bash
cd frontend

# 全量（只读）
./scripts/e2e.sh

# 指定设备
./scripts/e2e.sh --serial 192.168.31.132:5555

# 只跑某一类
./scripts/e2e.sh --class com.cobo.app.e2e.UiSmokeTest

# 复用已安装的包，不重新编译/安装
./scripts/e2e.sh --no-build --no-install

# 打开真实写入测试（点赞、关注，跑完会还原）
./scripts/e2e.sh --destructive
```

脚本会：

1. `assembleDebug` + `assembleDebugAndroidTest`
2. `adb install -r --no-incremental` 覆盖安装 app 与 test APK（保留登录态、草稿、历史）
3. `am instrument` 跑 `com.cobo.app.e2e` 包
4. 冷启动冒烟：强停、启动、`uiautomator dump` 检查「推荐 / 关注」和崩溃日志
5. 报告写到 `frontend/build/reports/e2e/`

设备必须已登录。没有 `session.json` 时，依赖会话的测试会被 `Assume` 跳过，而不是失败。

接口类测试会先启动 `MainActivity` 再发请求：部分 ROM 会限制没有前台 Activity 的进程联网，导致本来两秒的请求变成读超时。

## 实测

132（OnePlus Ace 2V / ColorOS）上全量 58 个用例通过，耗时约 310 秒，冷启动冒烟通过。1.0.23 起新增 5 条用例（回顶刷新 1 条、编辑记录 4 条），已单独跑通。

## 测试发现并修复的问题

- **信息流重复 id 崩溃**：接口偶尔返回重复微博，`LazyColumn` 的 key 冲突会直接抛 `IllegalArgumentException`。信息流、收藏、附近、私信、评论都改为按 id 去重，评论与私信 key 再加下标兜底。
- **正文链接打开空白网页**：微博正文里「全文」是 `/status/<id>`、@用户 是 `/n/<name>`，都是站内相对路径。原样交给 WebView 会按 `file:///` 解析并报 `ERR_ACCESS_DENIED`。现在相对路径补成 `https://m.weibo.cn` 绝对地址，指向单条微博的链接直接进应用内详情。
- **草稿列表不刷新**：从草稿箱打开草稿再返回时，列表还停在“已移除”的旧状态，看不到刚回来的草稿。`DraftsScreen` 现在监听导航栈，回到草稿箱时重新读取本地草稿。

## 断言方式

- 页面锚点使用 Compose `testTag`，通过 `Modifier.semantics { testTagsAsResourceId = true }` 暴露成 UiAutomator 的 resource-id，例如 `bottom_tab_feed`、`feed_card_0`、`settings_dark`。
- 文案断言使用真实界面文本（`推荐`、`微博正文`、`热门评论`、`设置` 等）。
- 接口类断言直接调用 `App.repo`，验证真实响应的模型字段，不 mock。
- 缓存类断言比较缓存文件的 `lastModified()`：命中缓存不写文件，联网才会重写。

## 状态与清理

- 每个 UI 测试启动一个新的 `MainActivity`，结束时 `finish()`，并从 `logcat` 检查本应用是否有 `FATAL EXCEPTION`。
- 测试开始会切回「微博」Tab，避免上一个测试持久化的 Tab 影响下一个。
- 草稿测试在 `finally` 里按文本清理，即使断言失败也不留下草稿。
- `--destructive` 的点赞/关注测试在 `finally` 里还原服务端状态。
- 设置里的「清理缓存」会清空内容缓存，属于可恢复操作；后续页面会重新拉取。
- 退出登录只验证弹窗和取消，不会真的清会话。

## 已知不覆盖

- 登录页：需要人工完成短信/图形验证码，无法自动化。
- 发微博、评论、转发、上传图片/视频：会产生真实公开内容，套件不执行。
- 多账号切换、移除账号：会改用户账号数据，未纳入默认套件。
- 私信头像的**像素级**渲染：UiAutomator 只能拿到文本与节点，头像 URL 非空由 `ApiContractTest#messages_includeSenderAvatar` 保证。
- 通知未读角标、收藏动作、视频上传：上游 Web API 没有对应能力（见 [`03-功能清单.md`](03-功能清单.md)）。

## 写新测试

1. UI 元素优先加 `testTag`，不要靠坐标。
2. 用 `UiE2eTest` 的 `waitTag / waitText / tapTag / scrollToTag`，它们带超时与重试。
3. 需要真实接口就继承 `DataE2eTest`，用 `io { App.repo.xxx() }`。
4. 会改账号状态的用例必须检查 `destructive` 并在 `finally` 还原。
5. 跑单类验证：`./scripts/e2e.sh --class com.cobo.app.e2e.YourTest`。
