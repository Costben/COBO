> Kotlin + Compose 客户端，UI 基于本地 COUI（ColorOS 17 设计语言）。

## 3. COUI 接入

COUI 不走 Maven Central，而是从本地 fork 发布 Android + KMP 元数据：

```bash
cd frontend
./scripts/publish-coui.sh
```

脚本会执行（7 个模块）：

```bash
cd ../coui
./gradlew \
  :coui-core:publishAndroidPublicationToLocalRepository \
  :coui-core:publishKotlinMultiplatformPublicationToLocalRepository \
  ... \
  -x dokkaGenerate
```

产物落在 `coui/build/repository/local/io/github/suqi8/coui/kmp/`，版本形如
`1.2.0-<git-hash>-SNAPSHOT`。`frontend/settings.gradle.kts` 已把该目录加入仓库列表。

> 注意：每次重新发布都会重建 `build/repository/local`，必须一次性发布全部模块，
> 否则先发布的 `coui-core` 等会被后一次发布清掉。

## 9. 设计说明

- 主题：`COUITheme` + `ThemeController`，支持跟随系统 / 浅色 / 深色。
- 字号：通过 `LocalDensity.fontScale` 叠加用户倍率，所有 `sp` 文本统一缩放。
- 卡片：`Card` + 12–14dp 内边距，列表间距 8dp；圆角与按压反馈由 COUI 提供。
- 九宫格：1 张按原比例，2–4 张两列，5–9 张三列。
- 图标：底部导航与通用操作使用 `COUIIcons`；转发/评论/心形/@/#/表情为自绘矢量，全部自绘。
- 交互：所有页面支持系统返回；WebView 优先网页内后退。
- 富文本：`Html.fromHtml` → 过滤 U+FFFC → `AnnotatedString`；`#话题#` / `@用户` / URL 通过 `LocalLinkHandler` 在应用内 `Route.Web` 打开。

## 10. 动画、底栏与持久化

### 10.1 动态详情：从卡片展开

对齐 c001apk Compose 端的 `ExpandFrame`：

- 信息流卡片用 `Modifier.expandOrigin(origin)` 记录卡片的完整矩形（`positionInRoot()` + `size`，不用 `boundsInRoot()`：后者会被列表视口裁剪，半露的卡片会把详情页起始框压矮）与 17dp 圆角；点击时把 `origin` 一起压栈。
- 详情页用 `graphicsLayer` 从卡片矩形插值到全屏：
  - 进入 420ms，返回 220ms，几何曲线 `CubicBezier(0.3, 0, 0.1, 1)`。
  - `translationX/Y = lerp(card.left/top, 0, p)`，`scale = lerp(card.width, screenW, p) / screenW`，锚点 `(0, 0)`。
  - 圆角从 17dp 插值到屏幕物理圆角，`clip = true`。
  - 黑色遮罩 alpha `0.3 * p`。
  - 页面内容 alpha：进入时 `(fade - 0.25) / 0.3`（约 105ms 开始、231ms 完成），返回时随 `fade` 淡出。
  - 内容额外 `translationY = -statusBarTop * (1 - p)`，让整页在卡片框里先贴住状态栏。
- 被点卡片用 `GraphicsLayer` 持续录制自己的内容，在 0–105ms 内叠在详情页之上淡出；详情内容 105–231ms 淡入，两者不重叠，避免空白帧和双重曝光。
- 卡片快照画在**详情页自己的裁剪层内**，只按宽度等比缩放（`k = 页面宽 / 卡片宽`），超出卡片高度的部分裁掉；不再分别按宽高缩放，卡片不会在起始帧或返回末尾被纵向压扁，也不会盖到卡片以外的列表和底栏。
- 返回手势把页面带回卡片后（`LandedProgress = 0.2`）就视为“已归位”：此时松手直接返回信息流，不再弹回展开成详情页。
- 没有 `origin` 的详情入口（链接、历史、转发块）自动退回 320ms 整页滑入。

### 10.2 设置页：整页从右滑入

- 320ms，`CubicBezier(0.3, 0, 0.1, 1)`。
- 新页 `translationX` 从 `+W` 到 0；下层页面从 0 到 `-W/4`，返回时反向。
- 两页 alpha 均为 1，无淡入淡出；移动页按屏幕圆角裁剪。
- 所有压栈页面保持组合：从详情/设置返回时，信息流不重新请求，滚动位置也保留。

### 10.3 悬浮底栏

- 使用 COUI `BottomFloatingAccessoryNavigationBar`，共 5 个控件：左侧刷新圆钮、中间连在一起的 微博 / 消息 / 我 三格胶囊、右侧发微博圆钮。
- 结构尺寸按相册底栏缩小到 0.86 倍（胶囊与圆钮约 48dp），文字保持原有物理字号。
- 底栏覆盖在内容之上，信息流、消息与主页从胶囊下方穿过，列表底部留出 66dp + 导航栏 inset，最后一条仍能滚到胶囊上方。
- 内容层通过 `Modifier.layerBackdrop` 录制，`LocalBackdrop` 提供给底栏；胶囊因此有 COUI 的边缘高光与模糊透光，而不是纯色填充。

### 10.4 返回动画

- 开启 `enableOnBackInvokedCallback`，根节点用 `PredictiveBackHandler` 接管全部返回：手势进度直接驱动详情收起或页面向右滑出，松手过阈值完成出栈，未过阈值 180ms 回弹。
- 手势进度只在 `graphicsLayer` / `drawWithContent` 里读取，不触发整页重组；拖动过程中页面跟手，不会掉帧。
- 详情页的 30% 压暗只在进入时绘制，返回时不再压暗。之前返回一开始就把压暗层从 30% 淡到 0，画面会突然变亮，看起来就是“闪一下”。
- 退场时被点卡片从 `frameProgress` 0.4 到 0.08 淡回页面之上，页面同步淡出，两者交叉过渡，不会在末段露出空白填充或整块变亮。
- 卡片快照里的底色是半透明白，绘制前先铺一层页面底色；否则快照的透明底会透出详情页内容，卡片看起来比列表里亮一档，也就是之前末尾那一闪。
- 卡片在点击瞬间被录制，退场前用 `refreshKey` 让它重录一次，交还的是此刻的卡片而不是按下时的样子。
- 手势没有产生任何进度（例如系统直接判定为返回）时走 220ms 动画出栈，不会瞬间切走。
- 栈底再返回时消费掉手势并 `moveTaskToBack`，系统不会播放自己的缩放 + 压暗预览。
- `windowBackground` 跟随应用自己的深浅色设置（`#F0F1F2` / `#1E1E1E`），窗口过渡不会先闪白或闪黑。
- 发布页、WebView 等页面自己的 `BackHandler` 仍然优先。

### 10.5 页面配色

- 全 App 只有两层表面：页面背景与卡片。
- 页面背景统一为 `COUITheme.colorScheme.background`。浅色在 `CoboTheme` 里把 COUI 的 `background` 覆盖成 `#F0F1F2`，深色仍是 `#1E1E1E`。
- 卡片统一为 `surfaceContainer`：浅色纯白，深色是 10% 白叠在 `#1E1E1E` 上（实测 `#353535`）。之前浅色页面是纯白、卡片也是纯白，卡片层完全消失，信息流看起来像一整块白板。
- 详情页的正文和每条评论都用同一张 `Card`，与信息流卡片同色、同圆角、同 12dp 外边距和 8dp 间距；评论里的回复引用块用页面背景色，不再引入第三种灰。
- 转发块（被转发的原文）同理：浅色用页面背景 `#F0F1F2`，深色用 `surfaceContainer`（10% 白）。COUI 浅色的 `surfaceContainer` 就是纯白，与卡片同色，转发者评论和原文会糊成一片，所以浅色必须取页面色。
- 消息行、底部操作栏、详情展开时的页面填充、发布页与 WebView 的浮层都使用 `background`；`surface` 在深色是纯黑，已从界面里清除。
- `windowBackground`（`themes.xml` / `values-night` 与 `MainActivity`）同步为 `#F0F1F2` / `#1E1E1E`，窗口过渡不会先闪白或闪黑。
- 详情页的排序控件（热度 / 时间）与评论点赞徽章不引入新颜色：轨道是 `onSurface` 7%（浅）/16%（深）叠在页面上，选中胶囊取 `surfaceContainer`（浅色纯白）/`surfaceContainerHigh`（深色），徽章是 `onSurface` 12%（浅）/20%（深）叠在卡片上。`surface` 与页面背景同色，拿它当胶囊或轨道会直接消失。


### 10.6 顶栏

- 信息流使用 COUI `SmallTopAppBar` + `gradientGlass`，去掉「微博」标题。
- 三段控件（推荐 / 关注 / 好友圈）放在导航图标槽，左对齐，高度与右侧搜索按钮一致（40dp）；文字颜色与滑块随 pager 拖动同步。
- 分段控件按 COUI 的方式做按压反馈：关掉 `LocalIndication`（COUI 的 `COUIIndication` 会在整个矩形边界上铺状态层，按住时像一块方形阴影），改为按下的那一段缩放 0.96；滑块按 `232dp / 3` 的等分宽度定位，与文字中心对齐。
- 顶栏覆盖在列表上，列表首行从顶栏下方开始，滚动时内容从顶栏后面穿过；同一份 `LocalBackdrop` 同时供顶部与底部玻璃采样。
- 三个主页顶栏都显式传 `color = background`。`SmallTopAppBar` 默认取 `surface`，深色下是纯黑，会在状态栏压出一条 `#111111` 黑带。
- 详情页顶栏与信息流同一套：`gradientGlass` + 自己的 `LayerBackdrop`，内容从顶栏后面穿过。列表和顶栏不再由 `Scaffold` 的 `topBar` 分栏，而是顶栏浮在列表上方，`contentPadding` 顶部留出状态栏 + 顶栏高度。
- 深色模式下 `MainShell` 用主题 `background` 铺底，信息流页面、卡片、顶栏玻璃与分段控件都跟随 COUI 深色 scheme，不会残留白色底；背景绘制放在 `layerBackdrop` 之后，确保顶栏采样到的是深色页面而不是透明层。
- 下拉刷新只把指示器偏移到顶栏下方，内容仍从顶栏后面滚动；刷新文案使用中文。

### 10.7 内容持久化

- 当前信息流 Tab（推荐 / 关注 / 好友圈）写入 `SharedPreferences`；新安装默认「关注」，之后冷启动恢复上次停留的 Tab。
- `CacheStore` 把每个 GET 响应写入 `files/http-cache/<sha256(cookie + url)>.json`，总量超过 16MB 时按时间清理最旧文件。
- 进入页面先读缓存，不自动请求网络；只有下拉刷新、详情页刷新按钮、发布后刷新才 `force = true`。
- 缓存 key 包含 Cookie，账号切换/退出登录时整体清空，避免串号。
- 点赞只失效对应详情缓存；评论/转发/发布清空全部缓存，保证下一次进入拿到新数据。
- 进程被杀后冷启动，信息流仍能从磁盘恢复第一页；后续分页在滚动时按 URL 命中缓存。
- 设置页「清理缓存」同时清理 Coil 图片缓存与 HTTP 内容缓存。

### 10.8 媒体查看器
- 图片查看器是 `HorizontalPager`：图片处于 1× 时单指拖动不消费事件，交给 pager 翻页；放大后单指拖动平移，双指同时缩放与平移。左上角显示 `当前 / 总数`。
- 视频页手势层避开底部控制条：左半屏上下滑调窗口亮度，右半屏上下滑调媒体音量，操作时屏幕中央显示百分比。
- 长按画面 3× 播放，松手回到右上角所选倍速；倍速菜单提供 1.0× / 1.25× / 1.5× / 2.0× / 3.0×。
- 长按用独立的手势循环加 `longPressTimeoutMillis` 计时，不与同节点的拖动、点击检测共用 `detectTapGestures`，避免被拖动检测抢走。

### 10.9 搜索与楼中楼

- 搜索条使用 COUI `InputField`（胶囊、40dp、内建清除按钮），不再有独立的「搜索」按钮；提交走输入法搜索键，硬件回车由 `onPreviewKeyEvent` 兜底。
- `Settings.searchHistory` 把最近 10 条查询存进 `app` 偏好文件的 `search_history`（JSON 数组），去重后新的在前。
- 历史用 COUI `SearchHistoryView` 渲染，位置在搜索条与「微博热搜」之间，标签可点、右侧垃圾桶清空。
- 评论的楼中楼来自热评自带的 `comments` 预览与 `total_number`：先显示 1 条预览与「共 N 条回复」，展开后翻页请求 `comments/hotFlowChild`。
- `hotFlowChild` 的 `max_id` 回到 0 或者某页没有新增回复时视为到底，避免「展开更多回复」无限重复；到底后显示「收起」。
- 楼中楼与引用回复共用页面背景色的内嵌块，不新增第三种灰。
- 评论和每条楼中楼都能点赞、都能回复：顶层评论的「回复」把新回复写进它自己的楼中楼，楼中楼里的「回复」用该回复的 id 继续往下嵌。
- 回复成功后不再重拉列表，而是直接用 `comments/reply` 返回的 `data` 插到楼中楼最前面并展开——服务端列表有几秒延迟，重拉会看不到刚发的那条。
- 评论与楼中楼的点赞徽章常显（0 也显示），点赞走 `comment/like` / `comment/dislike`，与微博正文的 `attitudes/*` 不是一套。

### 10.10 回顶刷新与编辑记录

- 左下角的融合球一次做两件事：把当前信息流滚回第一条，再拉一次第一页。三个页面的 `LazyListState` 上提到 `TimelineScreen`，由 `feedTopEvents` 统一派发，切换 Tab 后位置仍然保留。
- 回顶是逐帧自绘滚动（`glideToTop`），不是 `animateScrollToItem`：整段约 0.3 秒，短距离也会走完整时长，不会一帧跳到位。
- 回顶结束后不直接刷新，而是让 COUI 的刷新球像手指下拉一样弹出来再刷新。为此本地 COUI fork 给 `PullToRefreshState` 加了 `startRefresh()`，并把视觉状态先置为 `Pulling`——`RefreshHeader` 的高度由状态推导，留在 `Idle` 时球不可见，只会在刷新开始时突然弹出。
- 详情页读取 `edit_count`，大于 0 时在正文卡下方显示「已编辑 N 次 · 查看编辑记录」，点开进入编辑记录页；信息流卡片不显示，避免噪音。
- 编辑记录走 `weibo.com/ajax/statuses/editHistory`：这个接口拒绝移动端 Referer，`Api.getDesktop` 单独带桌面 UA 与 `Referer: https://weibo.com/`，且不写 HTTP 缓存。
- 返回的 `statuses` 按时间倒序，最新一条即当前版本，页面用「当前版本」徽章标出；可见性变更（「从公开变为仅自己可见」）是只有 `history_type` 的条目，按一行说明渲染，不当成正文。
- `pic_ids` 是裸图片 id，拼成 `https://wx1.sinaimg.cn/large/<id>.jpg` 后复用 `ImageGrid`，点开仍进图片查看器。
